There are no accounts. CoursePilot works without one.

Chrome extension · learn.vcs.net

Your homework is buried in lesson plans. CoursePilot reads them and tells you what's due.

Our teachers don't use Moodle's calendar — it's empty. They write homework as prose inside lesson plans: "Unit 1A Test Thursday 8/27," halfway down a page nobody scrolls. CoursePilot reads those pages, pulls out the assignments and dates, and shows you the exact sentence it read them from.

Your coursework is read and worked out on your own machine. There is no CoursePilot server and no account. One optional feature is the exception — it's off until you turn it on, and it's the first thing the privacy section tells you about.

How it works

Four steps, none of them clever

  1. 1

    It reads your lesson plans

    Teachers publish homework as prose inside Moodle Book activities — the lesson plan for the day. CoursePilot opens the same pages you'd open yourself and reads the text on them.

  2. 2

    It finds the assignments and the dates

    A sentence like "Unit 1A Test Thursday 8/27" becomes a dated item attached to a specific course. It resolves the ordinary ways teachers write dates — weekday names, "next Friday," a bare 8/27 — into a real day on the calendar.

  3. 3

    It shows you the sentence it read

    Every item carries the wording it came from and a link back to the page. If the extension is wrong, you can see why in one glance instead of trusting it. This is the whole reason the thing is usable.

  4. 4

    It answers the three questions

    What's due, what's coming up, and what's late — sorted, colour-coded, and grouped by course. That's the whole product.

Privacy & data handling

Where the data goes, and the one place it can leave

CoursePilot is a content script. It runs inside the tab, on pages the student has already loaded and authenticated. Everything to do with their coursework happens inside the dashed boundary below. Exactly one path leaves it, it is off until the student turns it on, and it is drawn here rather than left for you to find.

What it can access
Pages on learn.vcs.net that the signed-in student can already open: their course list, their course pages, the lesson-plan books inside them, and the school-wide calendar. It uses the student's existing browser session — the same one the tab is already using — and asks Moodle for nothing beyond that.
What it sends
Out of the box, nothing. There is no CoursePilot backend to send anything to, no analytics, no error reporting, and no third-party script. Course content is read into memory in the tab and discarded when the tab closes.
The one exception, in full

CoursePilot has an optional Gemini layer. It is off by default and does nothing at all unless a student pastes their own Google API key into the extension's options page.

With a key present, a question the rule engine can't classify — the words the student typed into the chat box — is sent to Google's API so the model can work out what they meant. That is why generativelanguage.googleapis.com appears in the extension's host permissions, and you will find it there. With no key, that code path never runs and the request is never made.

Assignments and dates always come from the teacher's page. The model is used to understand the question, never to supply the answer — which is also why every item still shows the sentence it was read from.

What it stores
Display preferences only, in the browser's own storage on that device: light or dark theme, where the student dragged the widget, whether they hid it, and which rotation day each class meets on. No coursework, no names, no credentials — and nothing that is readable from another device.
Who can see a student's work
Only that student, in that browser. There is no shared account, no roster, no teacher view, and no administrator dashboard — because there is no server for any of those to live on.
If you want to verify it
The extension is plain JavaScript with no dependencies and no build step, and the demo on this page is that same code with sample data swapped in. Read the manifest: the host permissions are learn.vcs.net and generativelanguage.googleapis.com, and the second one is there solely for the optional feature above. Open your browser's network tab while you use it — with no API key set, you will see it make no requests of its own. I'm happy to walk anyone at the school through the source.

Honest limits

What it can't do

A tool that reads teachers' prose is going to be wrong sometimes. Here's exactly where, so nobody finds out the hard way.

  • It can't see grades, and it doesn't touch PowerSchool

    It reads course content on Moodle. Grades, GPA, attendance, and anything in PowerSchool are outside it entirely — different system, no connection to it at all.

  • Only school-wide events — not sports or clubs

    It reads the school calendar that everyone gets. Game schedules, practice times, club meetings, and anything that lives in a group chat aren't in it, so it won't tell you about them.

  • A class with no lesson plans is invisible to it

    If a teacher doesn't post plans on Moodle, there is nothing to read, and CoursePilot will say nothing about that class. It won't guess, and it won't quietly leave the gap unmentioned.

  • Every date is only as good as the sentence the teacher wrote

    If the plan says Thursday and the test moves to Friday in class, CoursePilot still says Thursday. It doesn't know what was announced out loud, and it can't tell a firm date from a maybe. That's exactly why it always shows you the sentence it read — so you're checking a teacher's words, not trusting a program's guess. This holds with the optional Gemini layer switched on too: it helps work out what you asked, and it still doesn't get a vote on when anything is due.

  • It's a student project, not a supported product

    One person maintains it, on one school's Moodle. It isn't a replacement for reading your syllabus, and it should never be the only place a due date lives.

Who built this

A student at the school it runs on

I'm a high-school student at VCS, and I built CoursePilot because I was opening eight courses every night to find out what was due.

It knows lesson plans live on tab 2 of every course here. It knows my Mandarin class meets on B days, and that the rotation is the one thing Moodle can't tell you, so it asks. It knows that "chem," "chemistry," and "Chemistry Honors" are the same class, because that's how people actually type. None of that is in any general-purpose tool — a company building for a thousand schools would never learn it.

It's a first draft, and I'd rather have it in front of people and be told what's wrong with it than polish it alone for another month.

Install

Getting it running

CoursePilot is not on the Chrome Web Store. It's loaded manually, in developer mode, the way unreleased extensions are — which also means Chrome will show you a banner about it, and that banner is correct.

  1. Get the extension folder from me

    The source repo is private for now, so there's nothing to link to yet — ask me and I'll send you the folder. Unzip it somewhere you won't delete by accident.

  2. Open Chrome's extensions page

    Go to chrome://extensions and turn on Developer mode, top right.

  3. Load unpacked

    Click Load unpacked and choose the folder you unzipped.

  4. Open learn.vcs.net

    Sign in as usual. The chat button appears in the bottom-right corner. It only ever runs on that one site — every other tab is untouched.

School iPads can't install Chrome extensions, so CoursePilot doesn't run there. The demo at the top of this page does, though — that's just a web page.

Nothing in the install asks for an API key. The Gemini feature described in the privacy section stays off unless you go and add your own.
